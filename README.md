# Steam Update Watch

Небольшой Python-скрипт, который следит за обновлением **установленной игры на компьютере, где он запущен**. По умолчанию — Rust (`252490`). Windows, Linux и macOS; Python **3.11+**, сторонние Python-пакеты не нужны.

## Что именно проверяется

Скрипт читает `steamapps/appmanifest_<AppID>.acf`, который записывает ваш клиент Steam. Он учитывает локальную установку и выбранную в Steam ветку игры; новости, SteamDB и публичные номера сборок не используются.

| Событие | Условие | По умолчанию |
| --- | --- | --- |
| Steam требует обновление | Новый `TargetBuildID` и флаг ожидающего/выполняющегося обновления | Только консоль |
| Загрузка подтверждена на этом ПК | Между двумя успешными проверками вырос `BytesDownloaded` для той же целевой сборки | Уведомление и звук |
| Установлена другая сборка | Изменился `buildid`, та же ветка и состояние полностью установленной игры | Уведомление и звук |

**Главное ограничение:** до получения первых байт нельзя обещать, что загрузка действительно доступна. Очередь Steam может существовать при отключённом интернете, проблемах CDN, расписании или занятом диске. Поэтому основной сигнал включён именно на фактическую загрузку. Скрипт сам не запускает загрузку, не меняет настройки Steam и не проверяет CDN отдельным скачиванием. Подтверждение относится к моменту получения байт и не гарантирует успешное завершение всего обновления; данные могут приходить и через локальную передачу Steam.

Скрипт отслеживает обновления уже установленной игры, а не первую установку. Смена ветки/откат в той же ветке тоже может выглядеть как другая сборка; это не обязательно новый публичный релиз.

Чтение каждые **2 секунды** не создаёт запросов к серверам Steam. Можно поставить 1 секунду. Но это не заставляет клиент чаще проверять наличие сборок: задержка зависит от Steam и от частоты записи манифеста. Очень быстрое обновление может быть замечено только после установки. Если Steam не записывает целевую сборку или счётчик байт в вашей версии клиента, подтверждение загрузки не появится; скрипт не заменяет это догадкой. Формат ACF — внутренний формат клиента, совместимость после изменений Steam не гарантируется.

## Скачать и запустить

1. Установите [Python 3.11 или новее](https://www.python.org/downloads/). На Windows включите добавление Python в PATH.
2. Скачайте ZIP репозитория через **Code → Download ZIP** и распакуйте либо клонируйте репозиторий по URL из кнопки **Code**.
3. Откройте терминал в папке проекта.
4. Создайте личный конфиг и запустите скрипт.

Windows (PowerShell):

```powershell
Copy-Item config.example.toml config.toml
py -3 steam_watch.py
```

Linux / macOS:

```sh
cp config.example.toml config.toml
python3 steam_watch.py
```

Остановить: **Ctrl+C**. Окно терминала должно оставаться открытым, компьютер — бодрствовать. Не запускайте несколько копий для одной игры с одним каталогом состояния.

## Настроить Steam

- Игра должна быть установлена, первоначальная установка завершена.
- Запустите Steam, войдите в нужный аккаунт и используйте онлайн-режим. Скрипт проверяет наличие процесса клиента; это **не** проверка его онлайн-режима.
- В свойствах игры → **Обновления** выберите автоматическое обновление/высокий приоритет, если такой пункт доступен в вашей версии Steam.
- Проверьте ограничения расписания и скорости в настройках загрузок. Закройте игру, если Steam откладывает загрузку во время её работы.
- Если вы хотите только ранний сигнал из очереди, включите `notifications.queued = true`. Тогда сообщение прямо укажет, что загрузка ещё не подтверждена.

[Steam описывает зависимость автоматических обновлений от настроек клиента](https://help.steampowered.com/en/faqs/view/71AB-698D-57EB-178C).

## Конфиг

Все настройки находятся в `config.toml`; пример с комментариями — в `config.example.toml`.

- `game.app_id`, `game.name`: ID игры из URL магазина и название для уведомлений.
- `game.steam_path`: папка клиента Steam; пустая строка включает поиск стандартных путей, включая Linux Flatpak/Snap. Дополнительные библиотеки читаются из `libraryfolders.vdf`.
- `game.manifest_path`: точный путь к ACF; имеет приоритет над автоматическим поиском. Для нестандартной установки, нескольких клиентов или нескольких копий игры задайте его явно.
- `watch.poll_seconds`: интервал локальных проверок, 1–3600 секунд.
- `watch.state_file`: каталог состояния относительно конфига. После перезапуска уже успешно обработанные события не повторяются. Удалите этот каталог для сброса истории.
- `notifications.desktop`, `notifications.sound`: системное уведомление и звук.
- `notifications.queued`, `notifications.installed`: оповещения об очереди и завершённой установке. Подтверждение загрузки всегда обрабатывается.
- `telegram.enabled`: отправка через Telegram; выключена по умолчанию.

Пример ручного пути на Windows:

```toml
manifest_path = 'D:\SteamLibrary\steamapps\appmanifest_252490.acf'
```

На macOS типичный путь: `~/Library/Application Support/Steam/steamapps/appmanifest_252490.acf`. На Linux: `~/.local/share/Steam/steamapps/appmanifest_252490.acf`. Игра может находиться в другой библиотеке.

Запуск с другим конфигом:

```sh
python3 steam_watch.py --config /path/to/my-config.toml
```

Отсутствие игры при старте приводит к понятной ошибке. Если Steam закрыт или файл временно не читается, скрипт ждёт с увеличением интервала до 60 секунд. После восстановления интервал возвращается к заданному; сравнение байт через такой перерыв не производится.

## Уведомления

Windows использует системное уведомление в области уведомлений через PowerShell, macOS — `osascript`, Linux — `notify-send` (пакет `libnotify-bin` в Debian/Ubuntu). Разрешите уведомления и проверьте режим «Не беспокоить». На Linux звук — терминальный звонок; для слышимого сигнала он должен быть разрешён в терминале. В headless-сеансе используйте Telegram и выключите desktop/sound.

Проверка каналов (на Windows замените `python3` на `py -3`):

```sh
python3 steam_watch.py --test-notification
```

Неудачные каналы повторяются через 60 секунд; успешные в том же процессе не отправляются повторно. При перезапуске до доставки всех каналов часть уведомлений может повториться. Ошибки Telegram выводятся без токена. Telegram делает запрос только при уведомлении/повторе, не при каждой проверке игры.

### Telegram, необязательно

1. Создайте бота через `@BotFather`, получите токен и отправьте своему боту `/start`.
2. Узнайте свой `chat_id` через официальный метод [`getUpdates`](https://core.telegram.org/bots/api#getupdates), вызвав его локально для своего бота; ID находится в `message.chat.id`. Не передавайте токен посторонним сервисам.
3. В конфиге включите `telegram.enabled = true`.
4. Задайте переменные окружения в том же терминале перед запуском.

PowerShell:

```powershell
$env:STEAM_WATCH_TELEGRAM_TOKEN = 'ваш-токен'
$env:STEAM_WATCH_TELEGRAM_CHAT_ID = 'ваш-chat-id'
py -3 steam_watch.py --test-notification
py -3 steam_watch.py
```

Linux / macOS:

```sh
export STEAM_WATCH_TELEGRAM_TOKEN='ваш-токен'
export STEAM_WATCH_TELEGRAM_CHAT_ID='ваш-chat-id'
python3 steam_watch.py --test-notification
python3 steam_watch.py
```

Переменные живут в текущей сессии терминала. Личный конфиг, состояние и `.env` исключены из Git. Не записывайте токен в скрипт или коммиты; команды с токеном могут сохраняться в истории оболочки.

## Диагностика и разработка

Прочитать сохранённый локальный статус один раз, без уведомлений и без записи состояния:

```sh
python3 steam_watch.py --once
```

Этот режим работает и при закрытом Steam; сохранённый статус не доказывает текущую доступность загрузки.

Проверки без Steam, Telegram и реальных уведомлений:

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q steam_watch.py tests
```

Тесты проверяют обнаружение библиотек, разбор ACF, переходы очереди/загрузки/установки, смену ветки, сброс счётчика, подавление повторов и повтор доставки. Реальное обновление Rust и системные уведомления нужно проверить на целевой машине: синтетические тесты не подтверждают поведение установленного Steam.
