# Steam Update Watch

Небольшой Python-скрипт, который следит за обновлением **установленной игры на компьютере, где он запущен**. По умолчанию — Rust (`252490`). Windows, Linux и macOS; Python **3.11+**, сторонние Python-пакеты не нужны.

## Раннее уведомление: можно ли запустить обновление вручную?

**Да.** Если локальный Steam уже отметил новую сборку как требуемую, скрипт уведомляет сразу, не дожидаясь скачивания. Вы открываете **Steam → Загрузки → Rust → «Скачать сейчас»** (кнопка/стрелка запуска загрузки). Именно это — основной сценарий по умолчанию. Очередь может быть запланирована на более позднее время; ручной запуск позволяет начать раньше расписания.

Дополнительная проверка через официальный **SteamCMD** ищет опубликованную сборку независимо от того, успел ли обычный Steam обнаружить обновление. Это предварительное уведомление: после него откройте клиент и проверьте игру. Пока клиент не обновил своё состояние, кнопка обновления может ещё не появиться. Скрипт не принуждает клиент к проверке и сам не запускает игру или скачивание.

| Событие | Условие | Действие |
| --- | --- | --- |
| Опубликована другая сборка | SteamCMD вернул отличающийся buildid выбранной локально ветки | Предварительное уведомление: проверьте Steam |
| Локальный Steam требует обновление | Новый TargetBuildID и флаг ожидающего/выполняющегося обновления в ACF | Раннее уведомление: откройте Загрузки и запустите вручную |
| Steam запросил обновление/проверку, цель ещё не записана | Флаг UpdateRequired без TargetBuildID, без флагов повреждённых/отсутствующих файлов | Осторожный ранний сигнал: проверьте Загрузки; новый релиз ещё не подтверждён |
| Загрузка подтверждена на этом ПК | Между двумя успешными чтениями вырос BytesDownloaded для той же целевой сборки | Отдельное уведомление о получении данных |
| Установлена другая сборка | Изменился buildid, та же ветка и состояние полностью установленной игры | Уведомление о завершённой установке |

Все сигналы включены по умолчанию. Если локальная очередь уже известна, повторный сигнал о публикации той же целевой сборки подавляется. История уведомлений сохраняется между запусками.

Скрипт читает `steamapps/appmanifest_<AppID>.acf` вашей установленной игры. SteamCMD работает с метаданными в анонимном режиме, без пароля аккаунта, без `app_update` и без скачивания игры. Смена ветки/откат тоже может давать отличающийся buildid — это не обязательно новый публичный релиз. Защищённые паролем ветки анонимная проверка не поддерживает; локальный мониторинг для них продолжает работать.

### Частота и границы проверки

- Локальный статус читается раз в **1 секунду**, без запросов к серверам Steam.
- Метаданные через SteamCMD проверяются не чаще раза в **60 секунд после завершения предыдущего запроса**, в отдельном процессе; локальный мониторинг не ждёт ответа. Это выбранный консервативный интервал, а не официальная гарантия отсутствия ограничений со стороны Valve. Сетевые ошибки увеличивают паузу до 15 минут.
- При нормальной работе предварительный сигнал приходит после очередного запроса и ответа SteamCMD. Задержка может превышать минуту; метаданные могут кэшироваться, клиент Steam может оказаться быстрее. Гарантии «раньше всех» нет.
- Интервал 1 секунда — частота чтения, не гарантия доставки: Steam записывает ACF по собственному расписанию, а уведомления/сетевые повторы занимают время.
- Публикация сборки и локальная очередь **не гарантируют доступность CDN**. Получение байт подтверждается отдельно. Не хватает сети, места или есть ошибка Steam — ручной запуск может завершиться ошибкой.
- Первоначальная установка должна быть завершена. Очень быстрое обновление иногда видно только после установки. Если клиент не записывает TargetBuildID/счётчики, сигнал очереди/скачивания может быть пропущен. Если TargetBuildID ещё не записан, есть осторожный сигнал о требовании обновления/проверки; он может относиться к проверке файлов, а не к новому релизу. ACF — внутренний формат Steam.

## Установить SteamCMD для самого раннего сигнала

Без SteamCMD остаётся полностью рабочий локальный сценарий: **очередь → уведомление → ручной запуск → подтверждение скачивания**. При его отсутствии скрипт прямо сообщает, что проверка публикаций выключена.

1. Установите SteamCMD по [инструкции Valve](https://developer.valvesoftware.com/wiki/SteamCMD) для своей ОС. Это отдельный инструмент, обычного клиента Steam недостаточно. Используйте отдельную папку SteamCMD, не папку установленной игры.
2. Один раз запустите его и дождитесь начального обновления самого инструмента; завершите командой `quit`.
3. В `config.toml` укажите полный путь в `release.steamcmd_path` или добавьте команду `steamcmd` в PATH. Поле — один исполняемый файл, без дополнительных аргументов. На Linux/macOS файл `.sh` должен быть исполняемым.

Windows:

```toml
[release]
enabled = true
steamcmd_path = 'C:\Tools\steamcmd\steamcmd.exe'
poll_seconds = 60
timeout_seconds = 45
```

Linux/macOS (если версия SteamCMD поддерживается вашей системой):

```toml
[release]
enabled = true
steamcmd_path = '/home/user/steamcmd/steamcmd.sh'
poll_seconds = 60
timeout_seconds = 45
```

При настройке существующего конфига редактируйте его секцию `[release]`, не добавляйте вторую с таким же именем. Пример `/home/user/...` замените своим фактическим путём.

Проверка вручную на Windows PowerShell:

```powershell
& 'C:\Tools\steamcmd\steamcmd.exe' +login anonymous +app_info_update 1 +app_info_print 252490 +quit
```

Linux/macOS:

```sh
/path/to/steamcmd.sh +login anonymous +app_info_update 1 +app_info_print 252490 +quit
```

В выводе должны быть данные `252490 → depots → branches → public → buildid` (для другой выбранной ветки — её имя). При отсутствии этих данных ранняя проверка не работает для этой игры/ветки. Не подменяйте Rust (`252490`) его выделенным сервером (`258550`): это разные приложения и сборки. При запуске скрипта ищите строку «Ранняя проверка публикаций: SteamCMD» и следите за последующими ошибками/таймаутами.

Метод сравнения buildid ветки описан [автором steamctl](https://github.com/ValvePython/steamctl/discussions/29); команды обновления кэша и чтения метаданных приведены в [документации проекта docker-steamcmd](https://github.com/GameServerManagers/docker-steamcmd#steamcmd-commands-and-convars).

## Скачать и запустить

1. Установите [Python 3.11 или новее](https://www.python.org/downloads/). На Windows включите добавление Python в PATH.
2. Скачайте ZIP репозитория через **Code → Download ZIP** и распакуйте либо клонируйте репозиторий по URL из кнопки **Code**.
3. Откройте терминал в папке проекта.
4. Создайте личный конфиг и запустите скрипт.

Windows (PowerShell):

```powershell
Copy-Item config.example.toml config.toml
py -3 steam_watch.py
```

Linux / macOS:

```sh
cp config.example.toml config.toml
python3 steam_watch.py
```

Остановить: **Ctrl+C**. Окно терминала должно оставаться открытым, компьютер — бодрствовать. Не запускайте несколько копий для одной игры с одним каталогом состояния.

## Настроить Steam, чтобы начать как можно раньше

1. **Держите клиент запущенным, аккаунт — в онлайн-режиме.** Компьютер должен бодрствовать. Скрипт проверяет процесс Steam, но не подтверждает его онлайн-режим.
2. **Rust → Свойства → Обновления:** выберите немедленное скачивание обновлений, если такой пункт есть в вашей версии клиента. В интерфейсе с прежними названиями — **«Высокий приоритет / Всегда обновлять эту игру раньше других»**. Режим «Только при запуске» не подходит для ранней автоматической загрузки.
3. **Steam → Настройки → Загрузки:** отключите ограничение времени автоматических обновлений и ненужный лимит скорости. Закройте игры перед ожидаемым обновлением либо разрешите загрузки во время игры, если это нужно.
4. После раннего уведомления откройте **Загрузки**, найдите Rust и нажмите **«Скачать сейчас»**. Очередь можно переупорядочить, чтобы Rust был первым. Не ждите назначенной Steam даты; запуск игры тоже заставляет Steam сначала обновить её.
5. Если пришло только предварительное уведомление о публикации, а обновления в клиенте ещё нет, дождитесь сигнала локальной очереди. Можно полностью выйти из Steam и открыть его снова, но ускорение обнаружения этим способом не гарантируется.

Настройки и ручное управление очередью описаны в [справке Steam](https://help.steampowered.com/en/faqs/view/71AB-698D-57EB-178C). Приоритет ускоряет обслуживание очереди, но не обещает проверку новых сборок с заданной частотой. Свободное место, скорость соединения и ошибки CDN тоже влияют на начало загрузки.

## Конфиг

Все настройки находятся в `config.toml`; пример с комментариями — в `config.example.toml`.

- `game.app_id`, `game.name`: ID игры из URL магазина и название для уведомлений.
- `game.steam_path`: папка клиента Steam; пустая строка включает поиск стандартных путей, включая Linux Flatpak/Snap. Дополнительные библиотеки читаются из `libraryfolders.vdf`.
- `game.manifest_path`: точный путь к ACF; имеет приоритет над автоматическим поиском. Для нестандартной установки, нескольких клиентов или нескольких копий игры задайте его явно.
- `watch.poll_seconds`: интервал локальных проверок, 1–3600 секунд.
- `watch.state_file`: каталог состояния относительно конфига. После перезапуска уже успешно обработанные события не повторяются. Удалите этот каталог для сброса истории.
- `notifications.desktop`, `notifications.sound`: системное уведомление и звук.
- `notifications.sound_file`: путь к своему аудиофайлу относительно папки скрипта или абсолютный. По умолчанию `assets/audio/phonk-killer.mp3`; пустая строка включает системный сигнал.
- `notifications.sound_duration_seconds`: длительность фрагмента (по умолчанию 15 секунд), `0` — весь трек. Проигрывание идёт в фоне и не задерживает проверку Steam; одновременно играет один фрагмент.
- `notifications.queued`, `notifications.installed`, `notifications.published`: оповещения об очереди, завершённой установке и публикации сборки. Включены по умолчанию; подтверждение загрузки всегда обрабатывается.
- `release.enabled`, `release.steamcmd_path`: включение ранней проверки метаданных и путь к SteamCMD.
- `release.poll_seconds`: сетевой интервал 60–3600 секунд после завершения запроса.
- `release.timeout_seconds`: таймаут одного процесса SteamCMD, 10–300 секунд.
- `telegram.enabled`: отправка через Telegram; выключена по умолчанию.

Пример ручного пути на Windows:

```toml
manifest_path = 'D:\SteamLibrary\steamapps\appmanifest_252490.acf'
```

На macOS типичный путь: `~/Library/Application Support/Steam/steamapps/appmanifest_252490.acf`. На Linux: `~/.local/share/Steam/steamapps/appmanifest_252490.acf`. Игра может находиться в другой библиотеке.

Запуск с другим конфигом:

```sh
python3 steam_watch.py --config /path/to/my-config.toml
```

При обновлении со старой версии включите `notifications.queued = true` и уменьшите `watch.poll_seconds` до 1 в своём личном конфиге. Отсутствующая секция `[release]` получает новые значения по умолчанию; явно заданные настройки сохраняют приоритет.

Отсутствие игры при старте приводит к понятной ошибке. Если Steam закрыт или файл временно не читается, скрипт ждёт с увеличением интервала до 60 секунд. После восстановления интервал возвращается к заданному; сравнение байт через такой перерыв не производится. Проверка публикаций через SteamCMD продолжается независимо от обычного клиента; для сравнения используется последняя успешно прочитанная локальная сборка/ветка.

## Уведомления

Windows использует системное уведомление в области уведомлений через PowerShell, macOS — `osascript`, Linux — `notify-send` (пакет `libnotify-bin` в Debian/Ubuntu). Разрешите уведомления и проверьте режим «Не беспокоить». Свой MP3 проигрывается через `afplay` на macOS, встроенный Windows MCI/PowerShell, а на Linux нужен `ffplay` (пакет ffmpeg) или mpv. В проект включён предоставленный трек Phonk Killer; повторное событие во время проигрывания не накладывает второй трек. Если путь к аудиофайлу пустой, на Linux звук — терминальный звонок; для слышимого сигнала он должен быть разрешён в терминале. В headless-сеансе используйте Telegram и выключите desktop/sound.

Проверка каналов (на Windows замените `python3` на `py -3`):

```sh
python3 steam_watch.py --test-notification
```

Неудачные каналы повторяются через 60 секунд; успешные в том же процессе не отправляются повторно. При перезапуске до доставки всех каналов часть уведомлений может повториться. Ошибки Telegram выводятся без токена. Telegram делает запрос только при уведомлении/повторе, не при каждой проверке игры.

### Telegram, необязательно

1. Создайте бота через `@BotFather`, получите токен и отправьте своему боту `/start`.
2. Узнайте свой `chat_id` через официальный метод [`getUpdates`](https://core.telegram.org/bots/api#getupdates), вызвав его локально для своего бота; ID находится в `message.chat.id`. Не передавайте токен посторонним сервисам.
3. В конфиге включите `telegram.enabled = true`.
4. Задайте переменные окружения в том же терминале перед запуском.

PowerShell:

```powershell
$env:STEAM_WATCH_TELEGRAM_TOKEN = 'ваш-токен'
$env:STEAM_WATCH_TELEGRAM_CHAT_ID = 'ваш-chat-id'
py -3 steam_watch.py --test-notification
py -3 steam_watch.py
```

Linux / macOS:

```sh
export STEAM_WATCH_TELEGRAM_TOKEN='ваш-токен'
export STEAM_WATCH_TELEGRAM_CHAT_ID='ваш-chat-id'
python3 steam_watch.py --test-notification
python3 steam_watch.py
```

Переменные живут в текущей сессии терминала. Личный конфиг, состояние и `.env` исключены из Git. Не записывайте токен в скрипт или коммиты; команды с токеном могут сохраняться в истории оболочки.


### Сымитировать обновление через 3 секунды

```sh
python3 steam_watch.py --simulate-update
```

На Windows: `py -3 steam_watch.py --simulate-update`.

Через 3 секунды придёт сообщение **[ТЕСТ]** об обновлении в очереди. Ещё через 3 секунды после обработки первого — о начале получения данных, затем через 3 секунды — об установленной сборке. Доставка уведомлений добавляет время к сценарию. После трёх этапов скрипт завершится.

Режим использует обычную логику обнаружения и реальные настроенные каналы (системное уведомление, звук, Telegram). События `queued` и `installed` учитывают соответствующие переключатели конфига. Steam и SteamCMD не нужны; файлы игры и история уведомлений не меняются. Все сообщения помечены **[ТЕСТ]**. Это проверка логики и доставки, а не доступности настоящего обновления.

В демонстрации каждый канал пробуется один раз на событие, без повторов через 60 секунд. Если доставка не удалась, сценарий всё равно пройдёт остальные этапы и завершится с кодом 1; причину смотрите в консоли. Режимы `--simulate-update`, `--test-notification` и `--once` нельзя комбинировать.

## Диагностика и разработка

Прочитать сохранённый локальный статус один раз, без уведомлений и без записи состояния:

```sh
python3 steam_watch.py --once
```

Этот режим работает и при закрытом Steam; сохранённый статус не доказывает текущую доступность загрузки.

Проверки без Steam, Telegram и реальных уведомлений:

```sh
python3 -m unittest discover -s tests -v
python3 -m compileall -q steam_watch.py tests
```

Тесты проверяют раннее уведомление до скачивания, разбор ответов SteamCMD, интервалы и отсутствие параллельных запросов, таймауты и backoff, работу при закрытом обычном клиенте, обнаружение библиотек, разбор ACF, переходы очереди/загрузки/установки, смену ветки, сброс счётчика, подавление повторов и повтор доставки. Реальный ответ SteamCMD, обновление Rust и системные уведомления нужно проверить на целевой машине: синтетические тесты не подтверждают поведение установленного Steam.
